工事写真DX V3.10.10

②「場所を選択」を棟 → 階数 → 部屋名 → 場所／区画の階層表示へ変更しました。
空欄を飛ばし、自然順（2階 → 10階）で表示します。親をタップすると開閉でき、青色の場所が選択中です。
共通の編集・削除ボタンは選択した場所に作用します。削除は写真0枚の場合に限り確認後に実行します。
写真がある場合は枚数を表示して削除を拒否し、確認後にも同一トランザクションで再検証します。
場所ID・IndexedDBの形式は変更していません。

検証：`python tests/location-tree.py`（Python playwright、Chromium、curlが必要）。
階層表示、自然順、開閉、編集選択、空場所削除、写真保護、削除時の写真追加競合、再読込を検証します。
`python tests/project-import.py` は空場所削除後の編集ZIP・写真ZIP・黒板設定・Excel出力も検証します。
ローカルJSZipを利用する場合、両テストに `JSZIP_PATH=/path/to/jszip.min.js` を指定できます。
ローカル起動：リポジトリ直下で `python -m http.server 8000`。ビルドやnpm依存関係の導入は不要です。

工事写真DX V3.10.9

V3.10.8を基準に、「① 現場を登録・選択」へ「編集プロジェクトZIPを読み込む」ボタンを追加しました。
現場未登録でも、保存済みZIPから現場情報・場所・元写真・写真順・黒板設定を復元して編集を再開できます。
読み込みの進捗とエラーを初期画面にも表示します。ZIP形式（version 1）とIndexedDBの保存先は従来と同じです。
同じ現場IDがある場合は従来の二段階確認後に置き換え、または別現場として追加します。
全画像の確認後、単一トランザクションで保存する既存処理を使用します。

Excelは棟ごとに最大60枚/シート（20ページ）、超過分は同じ棟の続きシート。1ページ3枚のVer43様式を維持。

検証（Chromium / Playwright）
- 現場0件の初期画面から45枚のZIP復元、現場・場所・写真メタデータの復元
- 場所の青色選択と共通編集ボタン
- 置き換え最終確認キャンセル時の全データ保持、確認後の置き換え、別現場追加
- 写真不足ZIPで保存しないこと、不正ZIPエラーの初期画面表示
- 45枚の編集プロジェクトZIP再出力
- 黒板ありVer43 Excel：画像45枚、15ページ（改ページ14件）、No.45、施工者E27、ZIP整合性
- ブラウザJavaScriptエラー0件

再実行：Pythonのplaywright、Chromium、curlが必要です。
`python tests/project-import.py`
ローカルのJSZipを使う場合：`JSZIP_PATH=/path/to/jszip.min.js python tests/project-import.py`

スマホ実機での端末間受け渡し、Excelアプリでの表示・印刷は未検証です。

黒板一括設定の表示修正
- 現場を開くと各写真の保存済み設定を読み戻します。写真間で異なるチェックは「—」、位置・サイズは「写真ごとに異なる（維持）」で表示します。
- 一括適用前の変更は「未適用」と表示し、写真ZIP・Excel出力を止めて適用を案内します。
- 混在項目は変更しなければ写真ごとの設定を保持します。一括適用は事前確認後、単一トランザクションで保存します。
- 設定適用後は作成済み提出ファイルの保存欄を閉じ、再出力を必要とします。
- 保存設定の再表示、混在値保持、未適用時の出力停止、適用キャンセル、再読み込み後の保持、Excelの実際の黒板描画への設定引き渡しを自動検証しました。
