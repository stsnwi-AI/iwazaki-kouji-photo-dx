# 岩﨑電気工事 工事写真DX V3.4
①現場 → ②場所（階数・部屋名・場所／区画）→ ③作業 → ④施工段階 → ⑤撮影。
写真に現場・場所・作業・施工段階を保存し、ZIPも「現場/階数/部屋名/場所/作業/施工段階」で整理します。
IndexedDB名は `iwasaki_v2` を維持しています。

## V2.9変更点
- 「この現場の定義を書き出す」を追加。写真を含まないJSONファイルを作成します。
- 現場一覧に「現場定義ファイルを読み込む」を追加。別の作業者・端末で同じ現場、場所、作業項目を共有できます。
- 同じ現場名・工事番号がある場合、既存現場を更新するか別現場として追加できます。
- 既存現場を更新する場合、既存写真と場所IDを保持し、新しい場所・作業だけを追加します。
- 写真データは現場定義JSONには含めません。

## V2.4から継続
- 現場単位ZIP: `現場名_工事写真_YYYYMMDD.zip`
- 全現場ZIP: `全現場_工事写真_YYYYMMDD_HHMM.zip`


## V2.9変更点
- JPEG撮影画像はブラウザ側で縮小・再圧縮せず、撮影された元JPEGデータをそのまま保存します。
- JPEG以外の画像形式の場合のみ、元の縦横サイズを維持してJPEG品質0.98で変換します。
- V2.5までの1800px上限・JPEG品質0.88による縮小圧縮を廃止しました。
- 高画質化により、端末内のIndexedDB使用容量とZIP容量はV2.5より増えます。


## V2.9変更点
- ②場所は「階数・部屋名・場所／区画」のうち1項目以上で登録可能。
- 空欄の場所項目は写真ファイル名・ZIPフォルダ階層・画面表示から省略。


V2.9追加：一般的な工事用小黒板レイアウト（工事件名・工事場所・施工内容・施工者）、施工者名保存、撮影済み写真の個別削除（ZIP出力からも除外）。


## V3.1 更新
- 作業項目に「納品」「搬入」「撤去」「試験測定」を追加。
- 「納品」「搬入」「試験測定」は施工前・施工中・施工後の選択を省略。
- 「撤去」は従来どおり施工段階を選択。
- 工程不要の3項目は、小黒板・写真ファイル名・ZIPフォルダにも施工段階を付けない。

V3.1追加：現場登録時に施工者を登録し、現場ごとに保存。前回施工者を初期表示し、小黒板へ自動反映。現場定義JSONの書き出し・読み込みでも施工者を共有。


## V3.4 更新
- 現場情報の編集機能を追加（工事名・工事番号・現場住所・担当者・施工者）。
- 現場IDは維持するため、現場名を変更しても撮影済み写真との紐付けは維持。
- 施工者の入力元を現場情報に一本化し、小黒板側の施工者入力欄を廃止。
- 撮影時は電子小黒板を焼き込まず、元写真を保存。
- ZIP出力時に最新の現場名・施工者を使って小黒板画像を生成。
- ZIP内に「01_黒板あり」「02_黒板なし」を同時出力。黒板なし側は保存済み元画像を使用。


V3.4修正版：既存現場にも標準作業項目「納品・搬入・撤去・試験測定」を自動追加。納品・搬入・試験測定は施工段階を省略し、撤去は施工前・施工中・施工後を選択。


V3.4追加：ZIP内に photo_manifest.json と photo_manifest.csv を自動同梱。写真No、現場情報、施工者、場所、作業、工程、コメント、撮影日時、黒板あり／なし写真パスを記録し、工事写真台帳との自動連携用データとして使用できます。


V3.4追加：撮影順とは別に台帳順を管理。作業項目の上下移動、個別写真の上下移動、photo_manifest.json/csvへsortOrder（台帳順）を出力。Ver43取込側は台帳順を優先して配置する。


## V3.5 変更点
- ⑤「台帳の写真順」を④撮影画面の直下へ移動。
- 作業項目単位の並び替えを廃止。
- 撮影済み写真そのものを↑↓で並び替える方式へ一本化。
- 写真の並び順を ledgerOrder / manifest の sortOrder として保存し、Ver43取込順に使用。
